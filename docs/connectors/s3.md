# S3 / Cloud Storage Sink

S3 is a **Pro** sink that writes pipeline records as JSON objects to S3-compatible
object storage.

> **Pro feature.** On the Community edition the S3 sink is gated: the type appears
> in the UI marked *Pro* and any saved config is rejected with an upgrade prompt.
> The real adapter ships in the Flux Pro / Enterprise edition. Activate a license to
> enable it. See [pricing](https://fluxdata.tech/pricing.html).

Flux writes objects over **HTTPS** to the storage endpoint, so — like the
[BigQuery](bigquery.md) and [external-database](external-databases.md) connectors —
it is an **outbound** integration: the sink can save with valid credentials and
still fail to deliver if the network path to the storage endpoint is blocked.

Each delivered record is written as a separate object whose key is rendered from a
template (see below), so one pipeline message becomes one object.

## Configuration

| Field | Required | Description |
| --- | --- | --- |
| `bucket` | yes | Destination bucket name. |
| `key_template` | yes | Object-key template; supports the placeholders below. |
| `region` | no | Bucket region (default `us-east-1`). |
| `endpoint` | no | Custom endpoint URL for MinIO / non-AWS providers (e.g. `http://minio:9000`). Leave blank for AWS S3. |
| `access_key_id` | no | Access key. If blank, Flux falls back to the environment / instance role (see Authentication). |
| `secret_access_key` | no | Secret key. Pair with `access_key_id`. |
| `content_type` | no | Object content type (default `application/json`). |
| `acl` | no | Canned ACL (default `private`). |

### Key template placeholders

The `key_template` is rendered per record. Supported placeholders:

- `{id}` — unique message ID (UUID)
- `{timestamp}` — ISO-8601 timestamp (e.g. `2026-02-05T12:30:45Z`)
- `{date}` — ISO-8601 date (e.g. `2026-02-05`)
- `{pipeline_id}` — the pipeline ID from delivery options
- `{field.path}` — a dotted path into the record (e.g. `{customer.region}`); an
  unresolved path renders as `unknown`

Example — partition objects by date and key by message ID:

```
key_template: data/{date}/{id}.json
```

## Provider compatibility

The adapter works with any S3-compatible storage:

- **AWS S3** — leave `endpoint` blank and set `region`.
- **MinIO** — set `endpoint` to your MinIO URL (e.g. `http://minio:9000`).
- **GCP Cloud Storage** — set `endpoint` to `https://storage.googleapis.com` and use
  HMAC keys for `access_key_id` / `secret_access_key`.

## Authentication

Provide an **access key pair** (`access_key_id` + `secret_access_key`) in the
config, or leave both blank to use ambient credentials — the standard AWS
environment variables (`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`) or the
**instance role** (IAM role / instance profile) of the host Flux runs on. Grant the
identity write access (`s3:PutObject`) to the bucket, plus `s3:ListBucket` /
`s3:HeadBucket` if you use **Test connection**.

## Networking & firewall

Flux connects **out** to the storage endpoint over **HTTPS (TCP 443)** — there is no
inbound rule to open. Flux's **egress** must be allowed to reach:

- the **AWS S3 regional endpoint** (e.g. `s3.us-east-1.amazonaws.com`), or
- your **custom `endpoint`** host (MinIO, GCS, etc.) on its configured port.

In a typical cloud deployment Flux sits in a private subnet behind a **NAT
gateway**, so that is the egress path to keep open:

- Allow outbound to the storage host on the egress firewall / network ACL / NAT
  gateway.
- If you run inside AWS with an **S3 VPC endpoint (gateway/interface)**, make sure
  the route table / endpoint policy permits the bucket, or requests are blocked even
  though the credentials are valid.

Use **Test connection** on the sink form to verify reachability and auth (a
`HEAD bucket`) before saving — it reports `access_denied` (403) and
`bucket_not_found` (404) distinctly.
